# 문맥별 사이드카 4차 구현·검증 기록

## 최신 반영 사항 · 2026-10-28

0.3.3 버전에서 Home 재설계(3개 카드 대시보드 및 대화방 매칭), 조직도 통합 쪽지 창(`NoteHostWindow`), 쪽지 작성 도우미 개편(서식 관리, 6종 AI 프리셋 다듬기, 최근 소통 카드), 단축키 커스텀 설정이 추가되었다. 자세한 내용은 [Home 재설계](home-dashboard.md)와 [조직도 쪽지 안내](organization-personalized-notes.md)를 참고한다. 최신 개발 소스는 저장소 스키마 11이며 단위 테스트 403개 통과, 합성 WPF 검사는 88개 화면, Release 오류·경고 0개다.

## 이전 4차 결과 · 2026-10-04

4차 최초 결과는 276개 테스트·60개 합성 화면이며 후속 쪽지 메뉴 수정으로 286개 테스트를 통과했다. 실제 /notes 목록에서 Main / Notes 감지와 수정본 재시작을 확인했다. 사용자 매뉴얼에는 실제 메인 메뉴/패널을 나란히 배치하고 개인정보를 흐림 처리한 이미지와 가상 자료 WPF 예시를 추가했다. 원본 개인정보 화면을 저장소에 추가하지 않았다.

현재 사용법은 [사용자 매뉴얼](../README.md), 기능별 확인 수준은 [구현 현황](implementation-status.md)과 [호환성 표](compatibility-matrix.md)를 기준으로 읽는다. 최신 개발 소스는 저장소 스키마 8이며 기존 0.3.1 배포 ZIP은 재생성하지 않았다. 최신 자동 테스트는 286개 통과, 합성 WPF 검사는 60개 화면, Release 빌드는 오류·경고 0개다. 대화 입력 직접 반영은 실제 미검증으로 제품에 노출하지 않고 초안 복사를 제공한다.

작성: 2026-10-04. 개발 소스 기준이다. 실제 화면 읽기와 합성 입력 검증을 구분하며, 기존 0.3.1 배포 ZIP은 갱신하지 않았다.

## 실제 화면에서 발견한 문제와 수정

온톡 5.4.3은 대화 목록의 미리보기와 메시지 본문을 MSAA의 `text` 컨테이너 아래 `statictext`로 노출한다. 기존 파서는 입력값을 제외하려고 모든 `text` 하위 요소를 건너뛰어 실제 대화 목록과 메시지를 0건으로 읽었다.

`MsaaReader`에서 검증한 대화 목록·대화창에 한해 포커스를 받을 수 없는 표시 컨테이너를 `contenttext`로 구분했다. 입력값은 읽지 않고 하위 표시 글만 파서에 전달한다. 포커스를 받는 입력, 숨김·비활성·암호 요소는 이 분류에서 제외한다. 로그인·친구·조직도·쪽지에는 이 분류를 적용하지 않는다.

대화 목록에서는 사람/방 행과 비어 있지 않은 미리보기가 있는 목록만 사용한다. 빈 미리보기를 가진 자기 프로필을 대화로 오인하지 않는다. 시각은 오전/오후 1~12시, 00~59분 형태만 허용한다.

읽기 전용 검사 앱에서 제품의 `NoteWatcher → MSAA → 파서`를 실행했다. 아래는 각 검사 당시 접근성에서 읽힌 항목 수이며 기관 전체 인원·부서 수나 대화 전체 이력 수가 아니다.

실제 이름·대화 본문·계정 정보를 소스, 합성 테스트, 화면 아티팩트에 옮기지 않았다. 검사 앱은 개수·문맥·지원 여부만 표시하고 운영 보관 저장소를 열지 않는다. 고정 창과 현재 부착 대상 추적 모드를 지원하며 10분 뒤 종료한다.

## 대화 입력 비교 기능의 구현 수준

답변 탭에 입력 글 가져오기, 현재 입력 글과 초안 비교, 실제 상대와 두 글의 확인 체크, 확인한 초안 반영 흐름을 합성 검증용으로 구현했다. 비교 화면은 360×480에서도 스크롤해 확인·반영 단추에 접근할 수 있다. 실제 입력 요소 확인이 실패했으므로 제품 `PanelWindow`는 입력 어댑터를 연결하지 않는다. 제품 답변 탭에는 초안 복사 경로를 제공하고 미검증 입력 단추는 노출하지 않는다.

`ChatInputWriter`는 반영 직전에 계정·활성 창 세션·프로세스·렌더 창·페이지·입력 요소·관찰 메시지의 연속성을 다시 검사한다. 온톡 입력 글이 비교 당시 값에서 바뀌면 덮어쓰지 않는다. 초안 수정이나 문맥 변경, 실패한 재검사는 이전 비교를 폐기한다. 반영 가능한 글은 줄바꿈을 포함한 500 UTF-16 코드 단위 이하이며, 다른 제어문자는 제외한다. 쓰기 응답만으로 성공으로 표시하지 않고 값을 다시 읽어 비교한다. 자동 재쓰기·Enter·전송·클립보드 대체 입력은 없다.

입력 읽기는 10초 안에 응답하지 않으면 실패 안내와 함께 UI를 풀고, 같은 읽기가 진행 중일 때 중복 작업을 시작하지 않는다. 늦은 읽기 결과는 초안이나 비교에 반영하지 않는다. 이 제한은 읽기 호출 자체를 강제로 종료하는 기능이 아니다.

**제품의 실제 입력 연동은 아직 확인되지 않았다.** `NativeChatInputBackend`는 단일 MSAA 입력 후보의 영역에서 UIA 요소를 찾아 `chatInputArea` ID, Edit 종류, 프로세스와 소속 창, 쓰기 가능한 ValuePattern을 확인해야 값을 조회한다. 전체 UIA 검색이 수 분 응답하지 않는 문제를 발견해 전체 검색을 제거했다. 문서의 제어 뷰 직접 자식 조회는 512개/8초 범위로 제한한다. 개별 외부 접근성 호출이 멈추는 경우까지 강제로 종료하지는 못하므로 UI의 읽기 대기 제한도 적용했다.

실제 검사에서는 이 조회가 완료되어도 정확한 입력 요소가 0개로 반환됐다. 따라서 제품 경로에서는 입력값 읽기·쓰기를 진행하지 않았고 초안 복사를 사용해야 한다. 앞선 화면 자동화 도구의 미전송 시험에서 여러 줄·이모지 입력과 전송 단추 활성화, 빈 입력으로 복원한 결과는 제품 백엔드의 검증 결과와 구분한다. 제품의 값 재읽기, 온톡 내부 작성 상태 갱신, 실제 반영 성공을 통과로 기록하지 않는다.

대안으로 Chromium의 읽기 전용 [ISimpleDOMNode 접근성 인터페이스](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/isimpledom/ISimpleDOMNode.idl)를 통한 입력 ID 확인도 시험했다. 현재 MSAA 객체에서는 이 인터페이스를 얻지 못했다. 해당 실험 코드는 제거했고, 확인되지 않은 경로를 값 변경에 사용하지 않는다.

방 고유 ID가 없어 동일 제목·동일 관찰 내용의 별개 방을 완전히 구분할 수 없다. 사용자가 실제 상대를 확인해야 하며, 다른 방에 이전 초안을 자동 복원하지 않는다. 사람/쪽지 연결 역시 표시 정보를 사용한 명시적 연결이다.

## 4차 최초 검증 (후속 쪽지 수정 전)

- 단위 테스트 **276개 통과**. 기존 문맥·계정·AI 근거·저장소 검증에 표시 컨테이너와 입력 구분, 자기 프로필 제외, 시각 검증, 입력 충돌·대상 변경·미지원·재읽기 불일치·중복 쓰기 방지·길이·여러 줄·이모지 검증을 추가했다.
- 합성 WPF 화면 **60개** 생성 및 검사. 제품의 초안 복사 화면에 미검증 입력 단추가 노출되지 않는 것도 확인한다. 검증용 입력 비교·확인 없이 반영 금지·초안 수정으로 비교 만료·실패한 재검사 후 이전 비교 폐기·읽기 시간 초과 후 UI 복구와 중복 조회 방지·늦은 결과 폐기·가져오기/되돌리기를 포함한다.
- 360×800/360×480 입력 비교·충돌 화면과 125%/150% 렌더를 확인했다. 배율 렌더는 실제 Windows 배율 변경·도킹 시험을 대체하지 않는다.
- 솔루션 Release 빌드 **오류·경고 0개**. UIA 참조에 필요한 WPF 프레임워크를 자동화·테스트·진단 프로젝트에 맞추고 검사 앱에는 제품과 같은 PerMonitorV2 매니페스트를 적용했다.
- 저장소 스키마는 8로 유지한다. 운영 계정의 보관 자료를 열거나 마이그레이션하지 않았으며, 실제 메시지 전송도 하지 않았다.

재현 명령:

```powershell
dotnet test tests/OnTalk.Sidecar.Tests -c Release --no-restore
dotnet build OnTalk.Sidecar.sln -c Release --no-restore
dotnet run --project tools/OnTalk.ContextPreview -c Release --no-restore -- artifacts/context-preview-phase4
```

합성 화면은 `artifacts/context-preview-phase4`에 있다. 실제 화면 검사는 `OnTalk.ContextPreview.exe --inspect <현재 창 핸들>` 또는 `--inspect follow`로 실행한다. 이 모드는 읽기 전용이며 반영 기능을 실행하지 않는다.

## 후속 수정: 쪽지 메뉴 감지

실제 쪽지 화면은 `#/notes` 경로와 `받은 쪽지`, `보낸 쪽지`, `보관 쪽지` 탭을 사용한다. 기존 감지가 `…쪽지함` 문구만 확인해 이 화면을 메뉴 미확인으로 처리했다. `/notes` 경로를 우선 판별하도록 수정해 목록 로딩 중에도 쪽지 메뉴를 인식한다. 경로가 없는 경우에는 세 탭의 표시 문구 또는 숨김 상태가 아닌 `pagetab` 이름을 함께 확인한다. 사이드바의 `쪽지` 문구만으로는 메뉴를 확정하지 않는다.

후속 검증은 단위 테스트 286개 통과, Release 빌드 오류·경고 0개다. 실제 쪽지 화면에서 제품 `NoteWatcher` → 파서 경로의 `Main / Notes` 결과를 읽기 전용 검사 앱으로 확인했고, 실행 중인 사이드카를 수정 빌드로 재시작했다. 실제 쪽지 본문과 사람 정보를 테스트나 문서에 저장하지 않았다.

## 남은 수용 검증

1. 제품 경로에서 정확한 대화 입력 요소를 얻는 방법을 보완하고, 비교·충돌 확인 후 미전송 반영과 원상 복원으로 내부 작성 상태까지 확인한다. 현재 환경에서는 초안 복사가 실제 사용 가능한 경로다.
2. 여러 줄·긴 메시지·첨부·시스템 이벤트·같은 제목의 방과 실제 다른 계정 전환을 확대 검증한다. 전체 이력을 읽었다고 간주하지 않는다.
3. 실제 배율 125/150% 도킹, 실표본 로컬 AI 품질, 오프라인·다른 PC 배포 수용 검증을 진행한다. 고유 ID나 전체 참여자 정보를 얻었다고 가정하지 않는다.
