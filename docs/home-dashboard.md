# Home 재설계: 친구·그룹별 업무 소통

2026-10-17 갱신, Asia/Seoul. 현재 개발 소스의 Home은 이 문서를 기준으로 한다. 기존 연락 준비 및 7개 영역 대시보드 설계를 대체해 핵심 3가지 영역으로 집중했다.

## 사용자에게 주는 도움

Home은 “이 그룹(또는 친구)에 어떤 쪽지를 보냈고, 최근 무슨 이야기를 나눴으며, 무엇을 이어서 확인할까?”에 답한다. 친구 목록과 그룹은 온톡에서 관리하고 sAIde는 그 관계에 연결된 발송 이력·대화 요약·열린 업무 맥락을 보여준다. 사람 찾기·조직 탐색·메시지 작성·업무 완료 처리·알림 설정은 기존 전용 화면을 사용한다.

## 정보 순서

| 영역 | 사용자가 확인하는 내용 | 다음 행동 |
|---|---|---|
| 그룹·친구·기간 | 어떤 관계와 자료를 보고 있는가 | 전체 그룹·개별 그룹 / 전체 친구·개별 친구 / 7일·30일·전체 선택 |
| 체크한 친구와 함께 | 온톡 친구 목록에서 체크한 친구(그룹 체크는 펼쳐 읽은 구성원) | `대화`·`쪽지` 단추: 온톡에서 체크한 친구 행을 우클릭해 같은 이름의 메뉴를 누른다 |
| 최근 쪽지 · 수신/발신 | 보관한 받은 쪽지(친구 연결·발신자 이름 일치)와 사이드카로 보낸 쪽지를 최신순으로 합친 목록 | 받은 원문·AI 요약, 보낸 내용·전체 수신자·전송 상태 상세 보기 |
| 최근 대화 | 지난 연락의 AI 요약과 결정·질문·요청 후보 | 분석한 원문·인용 근거 보기 및 친구 연결 해제 |
| 최근 업무 | 연결한 쪽지·대화에서 등록된 미완료 업무와 기한 | 기존 할 일 목록 창에서 상세 확인 및 완료 처리 |

360px 사이드카를 기준으로 세로 스크롤을 사용한다. 최근 쪽지(수신/발신) 5건, 최근 대화 3건, 최근 업무 3건을 우선 표시하고 나머지는 펼쳐 본다(`이전 쪽지`, `이전 대화 정리`, 업무 목록 창). 필터는 온톡의 읽힌 선택 신호 또는 사이드카의 직접 선택으로 지정한다. 수동 선택이 온톡 친구 선택이나 그룹 편집을 바꾸지는 않는다.

단체 대화·단체 쪽지는 온톡에서 사용자가 하는 순서(체크한 친구 우클릭 → `단체 대화`/`단체 쪽지`)를 그대로 자동화한다. 화면에 보이는 체크한 친구 행 하나만 우클릭하고 체크 상태는 바꾸지 않으며, 새 대화창(`windows/chat`) 또는 쪽지 창(`windows/note`)이 열렸는지 다시 확인한다. 온톡 5.4.9의 우클릭 메뉴는 본창이 아닌 별도 팝업 창(Chrome_WidgetWin)이며 항목이 클릭 동작을 알리지 않아, 팝업 창의 접근성 트리에서 항목 위치를 읽어 그 자리를 누른다. 메뉴 항목을 찾지 못하면 Esc로 메뉴를 닫고 직접 여는 방법을 안내한다. 친구 행의 체크는 MSAA 체크 상태 또는 CSS 클래스 `ant-checkbox-checked`로 읽는다. 실제 온톡 5.4.9에서의 수용 시험은 남아 있다.

## 자료 연결과 집계

- 친구의 표시 이름·직급·소속 해시(`DisplayIdentity`)로 연결을 유지한다. 화면 행 주소가 바뀌어도 유지하지만 고유 계정 ID로 인증한 연결은 아니다.
- **보낸 쪽지 이력(`GroupHistory`):** 사이드카의 작성 도우미로 발송한 기록(`DispatchRecord`) 중 수신자 이름이 현재 선택한 그룹·친구의 구성원 이름과 일치하는 것만 기간 안에서 최신순으로 집계한다. 전송 직전 검증에서 차단된 기록(`NotSent`)은 제외한다. 온톡 작성창이 수신자를 이름으로만 표시하므로 동명이인은 구분하지 못하며, 선택 범위에 동명이인이 있으면 주의 문구를 표시한다. ‘전송 단추를 누름’은 상대방 도착까지 확인한 것이 아니다.
- **최근 대화 정리(`HomeChatDigest`):** 대화창에서 선택한 원문을 분석하고 실제 상대를 선택해 Home에 연결한다. 선택 원문·AI 요약·검증된 인용 근거를 보관한다. 원문 선택을 바꾸면 이전 연결 제안을 비운다.
- **이어서 확인할 업무(`OpenTasks`):** 완료되지 않은 등록 업무 중 연결한 쪽지 또는 연결한 대화의 같은 방 힌트·메시지 키·본문에서 나온 것만 포함한다. 기간 밖의 오래된 미완료 업무도 숨기지 않고 표시한다.
- 기간은 서울 날짜 기준이며 보낸 쪽지는 사이드카 발송 기록 시각, 대화는 원문 관찰일을 사용한다. 온톡의 전체 송수신량 통계로 표현하지 않는다.
- 접힌 그룹·화면 밖 친구를 전체 동기화한 것으로 표시하지 않는다. 그룹의 표시 인원과 읽힌 인원은 구분한다.

## 저장·수명

스키마 9에서 관찰한 최신 친구 스냅샷(`home_people`)과 Home 대화 정리·친구 연결 테이블(`home_chat`, `home_chat_contact`)을 추가했고, 스키마 10에서 조직도 개인화 작업 테이블(`personalized_work`)을 추가했다. 이전 스키마 저장소는 암호화 사본을 남긴 후 마이그레이션한다. 계정별 SQLCipher DB와 기존 암호화 백업·복구에 포함된다. 일반 대화 정리는 메모리에서 사용하고 Home 연결을 누른 선택 원문만 추가로 보관한다.

Home 대화 연결을 모두 해제하면 해당 Home 정리와 보관 원문을 삭제한다. 이미 업무로 등록한 원문은 기존 업무의 자료로 유지한다. 계정의 보관 자료 전체 삭제에는 Home 자료도 포함된다.

보이는 동안 10초마다 자료 변경을 확인하되 같은 자료이면 화면을 다시 만들지 않는다. 다른 문맥이나 계정으로 바뀌면 갱신을 멈추고 Home의 상세창도 닫는다.

## 확인한 범위

그룹 발송 이력 집계 테스트를 포함해 전체 단위 테스트 330개 통과. 동명이인·중복 원문·서울 날짜 경계·기간 밖 열린 업무·대화 출처·계정 격리·재시작·연결 해제·이전 스키마 마이그레이션·암호화 백업 복구를 검사했다.

합성 WPF 전체 77개 화면 중 Home은 전체·그룹·친구·빈 상태·480px 높이·125/150% 렌더를 포함한다. 대화 정리→친구 선택→Home 연결 및 선택 변경 후 연결 제안 만료도 검사한다. 이미지는 가상 자료이며 실제 온톡 사용자의 이력이 아니다. 새 Home의 실제 온톡 수용·키보드 사용성·실제 배율 도킹 검증은 남아 있다.
