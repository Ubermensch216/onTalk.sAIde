## 최신 검증

- 단위 테스트 308개 통과. 개인별 치환·파일 가져오기·수신자 대조·저장 및 기존 Home/쪽지 시험을 포함한다.
- 합성 WPF 72개 화면: 개인화 작업의 일반/작은 화면을 포함한다. 360px 폭·480px 높이·125/150% 렌더, 그룹/친구 필터와 대화 Home 연결 검사. 실제 배율 도킹 시험과 다르다.
- Release 솔루션 빌드 오류·경고 0개.
- 실제 제품 NoteWatcher→MSAA→파서: 친구, 조직도, 대화 목록, 일대일/그룹 대화, 로그인 전환, 쪽지 메뉴 확인. 당시 관찰 수는 전체/고유 개수 보장이 아니다.
- 쪽지 메뉴는 /notes 우선, 경로 없는 화면은 받은·보낸·보관 세 탭을 함께 확인한다. 목록 로딩 중 감지와 메뉴 미확인 수동 대안을 제공한다.
- 실제 메인 메뉴와 실제 패널 캡처를 개인정보 흐림 처리해 README에 추가했다. 상세/작성/대화 원문 예시는 가상 자료로 구분한다.

## 원래 설계에서 조정한 구현 순서

1. 외부 의존성 없이 실행할 수 있게 편집기는 WPF RichTextBox로 시작했다. Tiptap/WebView2 전환은 후속 판단이다.
2. SQLite 암호화 배포 구성을 확정하기 전, 전체 데이터를 DPAPI로 암호화한 JSON 저장소를 사용한다. 검색은 현재 업무공간의 메모리 자료를 대상으로 한다.
3. 자동 연동의 제한과 무관하게 검증할 수 있는 수동 가져오기·분석·업무화·검색·편집 기능을 구현했다. 온톡과 자동 연결되었다고 표시하지 않는다.
4. 작업 중 발견한 `plan-review.md`는 다른 작업에서 작성된 검토 자료이므로 수정하지 않았다. 해당 문서가 보고한 Electron/UIA 제약은 후속 호환성 검증의 참고 근거이며 이 구현의 독립 검증 결과와 구분한다.

## 검증

- Debug 및 Release 빌드: 경고 0, 오류 0. Release 실행 폴더와 ZIP 패키지를 생성했다.
- 자동 검증 프로그램: 33개 테스트 통과. 업무공간 격리, 수신자 스냅샷, 날짜·알림, 암호화·손상·파일 무결성, AI 근거·취소·원격 차단, 의미 검색 캐시와 모델 버전 변경 등을 검사했다.
- WPF UI 검증: 쪽지 선택 유지, RTF 왕복, 초안 저장, 업무공간 전환 격리, 원문 이동, 6개 화면 렌더링을 확인했다. 실제 마우스·키보드와 한글 IME 사용성 전체를 검증한 것은 아니다.
- 배포 폴더의 실행 파일에서도 별도 테스트 저장소로 같은 6개 UI 검증을 통과했다. 검색·연결 화면의 최신 렌더링을 육안으로 확인했다.
- 실제 로컬 모델 시험: 합성 쪽지 두 건만 사용했다. `bge-m3:latest` 의미 검색 약 4.5초, `gemma4:e2b`의 짧은 쪽지 분석 약 19.6초. 두 시험 통과. 이 수치는 한 번의 실행 결과이며 일반 성능 보장이 아니다.
- 온톡 진단: 실행 프로세스 식별 경로는 동작했지만 현재 검사 환경에서 온톡 최상위 창을 얻지 못했다. UI 구조·본문 수집·발송·예약은 미검증이다. 쪽지 본문·로컬 DB·로그는 읽지 않았다.

실제 온톡 발송이나 예약 시험은 수행하지 않았다. Ollama 설정, 온톡 실행 옵션, 설치 파일은 변경하지 않았다. 네트워크를 차단한 실사용 시험은 아직 수행하지 않았다.
