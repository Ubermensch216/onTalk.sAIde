# 연동 기술검증 결과 (P0, 진행 중)

- 도구: [tools/OnTalk.Probe](../tools/OnTalk.Probe/Program.cs)

## 계획 검토 문서와 달라진 점

[plan-review.md](plan-review.md)는 "UIA 요소 2개, MSAA 하위 노드 0개"로 기록했다. 이번에는 활성화 신호(`activate`)를 보내기 전에 이미 트리가 읽혔다. 원인은 확인하지 못했다. 첫 조회 때 Windows의 접근성 프록시가 Chromium의 스크린리더 감지에 응답해 켜졌을 가능성이 있으나 추정이다. 그래서 사이드카는 연결할 때마다 `activate` 신호를 명시적으로 보내고, 트리가 비어 있으면 연결 불확실 상태로 둔다.

## 쪽지 창 구조 (테스트 쪽지 1건, 작성창 2개로 확인)

쪽지 창은 받은 쪽지·새 쪽지·답장 모두 같은 페이지(`windows/note/app.html`)이고 요소 54~73개, 읽는 데 약 0.1초다.

| 항목 | 읽히는 형태 | 판정 |
|---|---|---|
| 창 종류 | 제목 글자("받은 쪽지", "새 쪽지", "답장") | 지원 |
| 발신자 | 이름, "직급 │ 부서"가 각각 글자 요소 | 지원 |
| 시각 | "10월 2일 오후 07:51". **연도와 초가 없다** | 부분 지원. 연도는 수집 시점으로 추정하고 추정 표시를 남긴다 |
| 본문 | 줄바꿈이 보존된 글자 요소 하나. 화면과 15줄 모두 일치 | 지원 |
| 첨부 | 파일명, "열기", "저장" 순서 | 파일명 지원. 파일 확보는 미검증 |

| 작성창 수신자 | 이름만 나온다. 부서·ID 없음 | 부분 지원. 동명이인을 이름만으로는 구분할 수 없다 |
| 작성창 본문 | 입력창의 값으로 전체가 읽힌다 | 읽기 지원. 쓰기는 미검증 |

답장 창의 인용문에는 "받은 시간 : 2026-10-02 19:51:52"처럼 연도와 초가 있다. 받은 쪽지 창에는 없으므로 수집에는 쓰지 못한다.

## M1 실행 확인

- 어댑터가 읽은 발신자·시각·본문·첨부가 화면과 일치했다 (`OnTalk.Probe notes --content`).
- 패널이 받은 쪽지 창 오른쪽에 같은 높이로 붙었고, 앱을 다시 켜도 "이미 보관한 쪽지"로 인식했다.
- 감시 주기 0.8초, 쪽지 창 3개를 읽는 데 약 0.2초. 패널 메모리 약 50MB.
- WPF 하드웨어 렌더링은 이 PC에서 시작 직후 650MB를 썼다. 소프트웨어 렌더링으로 고정했다.
- 확인하지 못한 것: 창을 끌 때의 따라가기 느낌, 배율 125% 이상, 싱글창 모드에서 쪽지를 바꿔 볼 때의 동작, 여러 받은 쪽지 창.

## 입력 시험 (빈 "새 쪽지" 창, 전송하지 않음)

`OnTalk.Probe input`으로 입력창을 한 번 클릭한 뒤 Ctrl+A, Ctrl+V로 9개 문장을 차례로 붙여넣고, 끝나면 Ctrl+A, Delete로 비웠다.

| 항목 | 결과 |
|---|---|
| 마우스 클릭으로 창 활성화·입력창 포커스 | 성공. 보안 에이전트가 막지 않았다 |
| 붙여넣기 반영 | 9개 모두 입력창 값이 붙여넣은 글과 일치했고 바이트 표시가 바로 바뀌었다 |
| 바이트 계산 규칙 | **UTF-8 바이트 수, 줄바꿈은 1바이트.** 한글 3바이트, ✅ 3, ✔️ 6, 😀 4. 9개 사례 모두 일치 |
| 정리 | 비운 뒤 `0/4000 Bytes`로 돌아왔다 |
| 다른 창에 가려진 경우 | 활성화 없이 맨 위로 올린 뒤 진행했다. 가려진 채로는 클릭하지 않는다 |

남은 문제: 시험 전 클립보드에 글자가 아닌 내용(이미지 등)이 있었고 복원하지 못했다. 작성창 반영 기능(M4)은 클립보드의 모든 형식을 보존해야 한다.

판정: 본문 반영은 지원. 수신자 추가, 예약 설정, 전송 버튼은 아직 시험하지 않았다.

## M2 실행 확인

- 테스트 쪽지를 `gemma4:e2b`로 분석: 약 25초. 할 일 후보 2개 모두 근거 문장이 원문과 일치했고, 원문에 없는 기한은 만들지 않았다.
- 패널에 요약·할 일 후보·근거·기한 표시가 나왔다. 분석 결과는 저장되어 다시 열면 바로 뜬다.
- 확인하지 못한 것: 패널의 등록·완료·직접 추가 버튼과 할 일 목록 창, 마감 알림 창은 화면에서 눌러 보지 않았다(저장소 동작은 자동 테스트로 확인). 표본이 쪽지 1건이라 분석 품질을 일반화할 수 없다.

## M3 실행 확인

- 문자 검색: 발신자·직급/부서·본문·첨부 파일명에서 낱말을 글자 그대로 찾는다. 합성 쪽지 1만 건에서 드문 낱말 103ms, 흔한 낱말 2개 113ms(목표 1초). 이 속도라 FTS5 색인은 넣지 않았다. 색인 없이 훑는 방식이므로 건수에 비례해 느려진다.
- 뜻 검색(`bge-m3`): 합성 쪽지 8건·질의 7개에서 답이 있는 질의 6개 중 5개는 1위가 맞았고 1개는 공동 1위였다. 답이 없는 질의("휴가 신청 방법")에도 0.53점짜리 무관한 쪽지가 나왔다. 맞는 쪽지의 점수(0.32~0.60)와 겹쳐 점수 기준으로 걸러낼 수 없다. 그래서 뜻 검색 결과는 글자 일치 결과 아래에 "뜻 유사(참고)"로 따로 표시한다.
- 질의 임베딩 약 0.05초(모델이 올라와 있을 때), 쪽지 8건 임베딩 5.2초(모델 올리는 시간 포함).
- 실제 보관 쪽지 1건으로 검색 창 확인: "교육 시간"은 글자 일치 1건, "연수를 얼마나 들어야 하나"는 글자 일치 0건·뜻 유사 1건.
- 설계서의 "의미 질의 상위 5개 적중률 90%" 목표는 평가하지 못했다. 사람이 정답을 붙인 실제 쪽지 표본이 필요하다.

## 아직 확인하지 못한 것

1. 보낸 쪽지·보관 쪽지 창의 구조.
2. 예약 전송 설정 화면과 수신자 추가 화면의 구조.
3. 수신자 추가·예약 설정·전송 버튼의 조작.
4. 쪽지 목록의 가상 스크롤 범위와 쪽지 식별자 노출 여부.
5. 온톡을 재시작한 직후에도 `activate`만으로 트리가 켜지는지.
6. 보안 에이전트(GsNarMon, uMonitor)가 입력 주입을 막는지.
7. 조직 승인: 원문 로컬 보관, 접근성 경유 수집의 허용 여부. 기술 문제가 아니므로 사용자 확인 사항이다.
