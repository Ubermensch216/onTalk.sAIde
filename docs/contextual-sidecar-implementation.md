# 문맥별 사이드카 1차 구현 기록

2026-10-04 · 개발 소스 기준. 기존 0.3.1 배포 ZIP은 갱신하지 않았다.

이 문서는 1차 완료 시점의 기록이다. 이후 친구·조직도 지원과 저장소 변경은 [2차 구현 기록](contextual-sidecar-phase2.md)에 있다.

## 구현 범위

[전체 설계](contextual-sidecar-design.md)의 A(문맥 일치)와 B(쪽지 읽기/작성 분리)를 중심으로 구현했다. C~E의 사람 선택·대화 분석·대화 입력 연동은 후속 단계다. 실제 온톡에서의 수용 검증은 남아 있다.

| 화면 | 이번 구현 | 남은 연동 |
|---|---|---|
| 친구 | 연락 준비 화면, 사이드카 로컬 그룹 구성원 확인, 새 쪽지 초안·보관 검색 진입 | 온톡에서 선택한 사람/그룹 연동, 관련 업무 연결 |
| 조직도 | 담당자 탐색 목적 안내, 문의 쪽지 초안·보관 검색 진입 | 부서/사람 선택, 업무 검색 조건, 근거 있는 담당자 추천 |
| 대화 목록 | 목록 지원 화면, 보관 검색·공통 업무 도구 | 선택 방/참여자·미리보기 범위 읽기 |
| 대화창 | 대화 페이지 식별, 대화 지원 화면으로 전환 | 메시지/참여자 읽기, 흐름·결정·질문 분석, 답변 편집기·입력 반영 |
| 쪽지 목록 | 보관한 쪽지 검색, 새 쪽지 초안 진입 | 온톡 목록 선택/보관 자료 연결 |
| 받은 쪽지 | 현재 부착된 창의 기존 요약·근거·원문·첨부·업무 지원 | 실제 화면 전환과 늦은 분석 결과 검증 |
| 새 쪽지·답장·전체답장·전달 | 종류별 목적, 패널 편집기, 문구 삽입, AI 제안 비교·수락, 되돌리기, 인용 분리, 바이트 점검, 본문 반영 | 온톡 실화면에서 작성 종류/충돌/짧은 창·배율 확인 |
| 사용자 검색·알리미 | 이전 쪽지/초안을 숨기고 공통 도구만 표시 | 전용 기능은 이번 범위에서 제외 |
| 로그인·미확인 | 이전 작업 숨김, 로그인 시 작업 도구 비활성화, 미확인 메인 메뉴 수동 지정 | 실제 로그인/로그아웃·계정 전환 확인 |

안내 화면의 도구 설명은 해당 작업의 지원 방향을 함께 나타낸다. 대화 메시지 자동 요약·답변 작성 기능은 아직 동작하지 않으며 화면에도 제한을 표시한다. 메인 메뉴 자동 판별은 접근성 선택 상태와 고유 본문 표식을 사용한다. 선택 신호가 없거나 표식이 충돌하면 이전 메뉴로 추측하지 않고 수동 지정을 제공한다.

## 동작과 보존 규칙

- `OnTalkDock`의 부착 대상 HWND와 같은 창의 문맥만 표시한다. 다른 열린 받은 쪽지를 표시용 대체 자료로 선택하지 않는다. 기존 받은 쪽지 수집은 표시 선택과 별개로 유지한다.
- 내용 감시는 800ms 주기다. 메인 트리 전체 읽기는 활성 부착 대상에서 수행하며 100ms 위치 감시와 분리한다. 비쪽지 페이지를 영구 제외하는 캐시를 제거해 같은 창의 페이지 전환을 다시 판별한다.
- 계정 후보가 연결 허용된 계정과 일치할 때만 내용 트리를 읽는다. 읽기 전후 계정 후보가 바뀌면 해당 관찰을 폐기한다. 메인 트리에서 편집 가능한 입력값은 읽지 않는다. 계정 후보 판정은 기존 프로필 폴더 메타데이터 방식으로 로그인 세션의 확증이 아니다.
- 창 렌더러/프로세스 변경, 읽기→작성 전환, 작성 종류/인용 원문 변경을 독립 세션으로 구분한다. 본문 편집과 수신자 변경은 같은 세션을 유지한다. 폴링 사이에 같은 종류·같은 원문으로 작업이 교체되면 구별하지 못할 수 있다.
- 초안 슬롯은 계정 저장소 안에서 세션·작성 종류별로 분리한다. 자동 저장은 800ms 지연 후 수행하며 닫을 때도 저장한다. 재시작하거나 다른 작업이 된 초안은 확장 도우미의 보관 목록에서 본문을 불러온다. 수신자·예약을 자동 복원하지 않는다.
- 패널에서 확장 작성 도우미로 이동하면 같은 글을 넘기고 패널 편집을 잠시 막는다. 도우미를 닫으면 글·인용 선택을 패널로 돌려준다. 확장 도우미는 원래 작성 세션에 고정되어 다른 창을 자동 선택하지 않는다.
- AI 결과는 편집기를 즉시 덮어쓰지 않는다. 초안/작업 버전이 일치할 때 비교용 제안으로 표시하고 사용자가 수락해야 적용한다. 같은 글로 되돌려도 이전 버전의 제안은 무효다. 인용은 생성 결과에 합치지 않고 별도로 유지한다.
- 본문 반영은 기존 `ComposeWriter`의 최신 본문 비교·바이트 제한·반영 후 재읽기를 사용한다. 패널에서는 충돌 시 덮어쓰지 않는다. 확장 도우미의 기존 충돌 선택과 별도 전송 확인 흐름은 유지한다. 반영 자체는 전송하지 않는다.

## 검증

단위/저장소 테스트 **196개 통과**(기존 168개 포함). 작성 종류, 메뉴 신호의 충돌/미확인, 제외·로그인, 정확한 부착 대상 선택, 같은 창의 페이지 변화, 작성 세션/계정 격리·재시작 복원, 편집 버전의 만료, 목적별 로컬 AI 요청을 확인했다. AI 요청 테스트는 가짜 HTTP 응답을 사용한다.

WPF 합성 화면 도구는 온톡을 읽거나 조작하지 않는다. **문맥 14종과 확장 도우미를 두 높이로 렌더링한 30개 이미지**를 `artifacts/context-preview/`에 생성한다. 다른 문맥에 받은 쪽지가 남지 않는지, 작성 편집기가 나오는지, 로그인 대기 후 도구가 복구되는지, 확장 도우미의 제안 수락·되돌리기·만료를 검사한다. 친구·답장·미확인 메뉴·확장 도우미 이미지는 육안으로도 확인했다.

```powershell
dotnet test tests/OnTalk.Sidecar.Tests -c Release
dotnet build OnTalk.Sidecar.sln -c Release
dotnet run --project tools/OnTalk.ContextPreview -c Release -- artifacts/context-preview
```

현재 개발 환경에서는 네트워크 복원이 제한되어, 기존 로컬 패키지를 워크스페이스 캐시로 복원하고 `--no-restore`로 검증했다. 패키지 버전은 변경하지 않았다.

실제 온톡 메뉴의 선택 신호, 작성 종류별 본문 반영, 로그인/계정 전환, 대화 내용 확보, 125/150% 배율은 이번 구현에서 검증하지 않았다. 실제 쪽지 발송이나 예약 등록을 실행하지 않았다. 이전 연동 검증 결과를 이번 코드의 실화면 검증으로 대체하지 않는다.

## 다음 구현 순서

1. 온톡 실화면에서 문맥 판별과 작성 반영의 수용 시나리오를 확인한다. 접근성 선택 신호가 없으면 화면별 고유 신호를 추가한다.
2. 친구/조직도의 사람·그룹·부서 선택 파서와 확인 수준을 연결한다. 동명이인을 이름만으로 결합하지 않는다.
3. 대화 메시지·참여자·확보 범위 파서를 구현한 뒤 흐름·결정·미응답 질문과 답변 초안을 제공한다.
4. 근거 있는 업무 등록과 대화 입력 반영을 확장한다. 대화 지속 보관은 별도 보존 정책 뒤 구현한다.
