# 문맥별 사이드카 3차 구현 기록

## 최신 반영 사항 · 2026-11-12

이 문서는 3차 당시 결과(237개 테스트·52개 합성 화면)를 보존한다. 당시 중단됐던 실제 감시 검사와 대화 표시 본문 파서 확인은 4차에서 이어 완료했다. 검사 앱의 자동 종료는 현재 10분이다. 제품의 대화 답변은 초안 복사이며 실제 입력 요소를 얻는 방법과 내부 작성 상태 검증은 남아 있다.

현재 사용법은 [사용자 매뉴얼](../README.md), 기능별 확인 수준은 [구현 현황](implementation-status.md)과 [호환성 표](compatibility-matrix.md)를 기준으로 읽는다. 최신 개발 소스는 저장소 스키마 11(0.3.3)이며 최신 자동 테스트는 403개 통과, 합성 WPF 검사는 88개 화면, Release 빌드는 오류·경고 0개다. 대화 입력 직접 반영은 실제 미검증으로 제품에 노출하지 않고 초안 복사를 제공한다.

작성: 2026-10-04. 2차 이후 남은 대화 지원과 자료 연결을 구현했다. 개발 소스 기준이며 배포 ZIP은 변경하지 않았다.

후속 실제 감시/파서 확인, 표시 본문 누락 수정, 입력 비교 구현과 실제 입력 연동의 한계는 [4차 구현·검증 기록](contextual-sidecar-phase4.md)에 있다. 아래는 3차 당시의 기록이다.

## 구현한 기능

| 화면 | 지원 |
|---|---|
| 대화 목록 | 관찰한 방 이름·표시 참여자 글자 검색, 목록 미리보기, 빈 목록 안내. 미리보기로 요약하지 않음 |
| 대화창 | 접근성에서 읽힌 텍스트 원문 선택, 최근 10건 선택, 명시적 범위 갱신 |
| 대화 정리 | 선택한 범위의 흐름 요약과 결정·질문·요청 후보. 메시지 번호와 정확한 본문 인용을 검증하고 불일치 제외 |
| 대화 답변 | 짧은 메신저 답변 제안, 현재 글과 비교, 수락, 되돌리기, 초안 복사 |
| 대화 업무 | 사용자가 메시지·업무 제목·기한을 고르고 원문 인용을 확인해 등록. 선택한 텍스트의 읽힌 원문·인용·발신자 확인 수준·날짜/시각·수집 시각 보관 |
| 친구·조직도 | 자연어 질문에서 로컬 AI 검색어 제안. 사용자가 검토 후 적용하면 관찰한 목록의 글자 일치 근거로 후보 표시 |
| 사람의 보관 자료 | 이름 일치 후보에 대해 직접 연결/해제. 사용자가 연결한 자료는 이름 후보 8건 범위와 별도로 최대 50건 표시 |
| 업무 목록·검색 | 대화 업무의 출처와 등록 당시 원문 표시. 받은 쪽지로 위장하거나 직접 추가로만 표시하지 않음 |

쪽지 전용 편집·읽기 기능과 제외 메뉴 정책은 유지한다. AI는 기존과 동일한 루프백 Ollama만 사용한다. 대화 AI 실패 시 원문 선택·직접 편집·복사·수동 업무 등록은 계속 사용할 수 있다.

## 문맥과 보관 규칙

- 새 메시지나 읽기 범위 변화가 생겨도 분석에 선택한 스냅샷과 초안을 교체하지 않는다. 알림을 표시하고 원문 선택 탭에서 다시 불러온다.
- 선택/글/활성 문맥이 바뀌면 오래된 제안은 수락하지 않는다. AI 입력은 최대 80건·본문 합계 12,000자로 제한한다.
- 방 고유 ID를 얻지 못했다. 창 세션, 표시 상대 정보, 연속 관찰 메시지의 겹침으로 변화 신호를 감지한다. 겹침이 없거나 상대 정보가 바뀌면 새 세션으로 분리한다.
- 다른 창으로 부착 대상을 바꾸면 대화 도우미를 폐기한다. 편집한 글은 계정별 초안 복구 목록에 남기지만 다음 방에 자동 복원하지 않는다.
- 동일 제목·동일 관찰 내용인 별개 방은 현재 정보만으로 완전히 구분할 수 없다. 전체 참여자나 내가 작성한 메시지를 추정하지 않으며 발신자 근거가 부족하면 `발신자 미확인`으로 표시한다.
- 업무 등록은 명시적으로 선택한 텍스트를 보관하는 행동이다. 그 외 대화 원문과 AI 정리는 메모리에서만 사용한다. 대화 전체를 자동 보관/검색하지 않는다. 텍스트가 여러 접근성 노드로 나뉘면 일부만 읽힐 수 있어 완전한 메시지 사본으로 간주하지 않는다.
- 사람/쪽지 연결은 이름·직급·소속 표시 정보에 대한 사용자의 연결이다. 고유 ID 인증이 아니다. 동일 표시 정보를 가진 여러 행에서는 연결 버튼을 비활성화한다. 인사이동으로 표시 정보가 바뀌면 연결을 자동 승계하지 않는다.

## 저장소

스키마 7→8: `task_chat_source`, `contact_note_link` 추가. 기존 받은 쪽지·업무·수신자 그룹·연락 준비 그룹은 유지한다. 이전 DB를 자동 백업하며 7에서 이동하면 `notes.db.v7.bak`를 남긴다. 업무/쪽지 삭제 시 관련 출처/연결은 외래키로 함께 삭제된다. 암호화 백업·복구에 새 연결도 포함한다.

이 버전으로 연 저장소는 이전 배포판과 혼용하지 않는다. 운영 계정의 저장소는 이번 검사에서 열거나 마이그레이션하지 않았다.

## 확인한 범위

- 실제 온톡 5.4.3의 열린 대화창: `windows/chat/app.html?chat#/chat`, 날짜→시각→본문 순서, 표시 상대 정보와 `chatInputArea` 입력란을 확인했다. 입력값 변경이나 전송은 하지 않았다.
- 실제 대화 목록: `renderer/app.html#/chatrooms`, 사람/방 행과 별도 미리보기 구조를 확인했다. 목록 로딩 중의 빈 자료와 완료 후 자료를 구분했다.
- 실제 내용·사람 정보는 소스/합성 테스트/화면 아티팩트에 저장하지 않았다.
- 제품 `NoteWatcher → MSAA → 새 파서` 경로를 확인할 읽기 전용 검사 창을 추가했다. 본문/계정/이름 대신 개수·문맥만 보여 주며 2분 뒤 닫힌다. 실행 후 사용자가 Escape로 컴퓨터 사용을 중단하여 검사 결과를 확인하지 못했다. 실제 통합 검증 통과로 기록하지 않는다.
- 단위 테스트 **237개 통과**: 날짜/발신자 미확인, 숨긴 자료·입력·그래픽 제외, 중복 메시지 순번, 목록 분리, 연속 범위/새 세션, AI 원문 근거, 짧은 답변 정책, 검색어 응답 검증, 계정 격리, 출처 삭제, 실제 합성 v6/v7 마이그레이션, 암호화 백업·복구.
- 합성 WPF 화면 **52개**: 기존 44개와 대화 네 탭의 360×800/360×480 화면. 원문 고정, 편집 후 늦은 제안 거절, 제안 수락/되돌리기, 중복 업무 방지, 다른 방 초안 격리, 검색 상세의 대화 출처를 추가 검증했다.
- 솔루션 Release 빌드: 오류·경고 0개. 합성 화면은 `artifacts/context-preview-phase3`에 있으며 운영 자료가 아니다.

재현 명령:

```powershell
dotnet test tests/OnTalk.Sidecar.Tests -c Release --no-restore
dotnet build OnTalk.Sidecar.sln -c Release --no-restore
dotnet run --project tools/OnTalk.ContextPreview -c Release --no-restore -- artifacts/context-preview-phase3
```

## 남은 검증과 기능

1. 실제 감시/파서 출력에서 친구·조직도의 선택/부분 범위, 대화 목록/메시지 개수를 확인하고 계정·방 전환을 검증한다.
2. 대화 입력란의 값 재읽기, 내부 상태 갱신, 여러 줄 입력 동작을 확인한 뒤 입력 반영을 제공한다. 현재는 복사만 지원하며 전송 동작은 연결하지 않았다.
3. 여러 줄 메시지·첨부·시스템 이벤트·그룹방·동일 제목 방의 실제 접근성 구조를 확대 검증한다. 현재 파서는 관찰한 날짜/시각 뒤의 텍스트 형태만 지원한다.
4. 사람/방/메시지의 고유 ID와 전체 참여자 정보를 안전하게 얻을 수 있는지 확인한다. 현재 연결은 약한 연결이며 동일인·미해결 질문·담당자·결정 확정을 자동 판정하지 않는다.
5. 실표본의 로컬 AI 품질, 배율 125/150%, 실제 도킹과 오프라인 배포 수용 검증을 진행한다.
