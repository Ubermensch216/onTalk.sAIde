# 문맥별 사이드카 2차 구현 기록

2026-10-04 · 개발 소스 기준. [1차 구현](contextual-sidecar-implementation.md)에 이어 전체 설계 C의 친구·조직도 지원을 추가했다. 기존 배포 ZIP은 갱신하지 않았다.

## 제공하는 기능

| 작업 | 구현한 지원 |
|---|---|
| 친구에서 연락할 사람 고르기 | 확인한 이름·직급·소속·상태 목록, 선택 신호가 있으면 대상 연결, 없으면 사이드카에서 명시적으로 선택 |
| 온톡 그룹에서 연락 준비 | 그룹 표시명·표시 인원·관찰한 구성원 연결, 그룹 체크 신호 반영, 읽은 구성원만 선택 |
| 조직도에서 담당자 찾기 | 펼친 트리의 부서 경로와 사람 목록, 부서/사람 선택, 담당업무·소속·이름·직급 글자 검색과 후보 근거 |
| 사람 상세 확인 | 표시된 상세의 담당업무·직장전화·메일을 읽고 확인 시각 표시. 마우스를 옮겨 상세가 사라져도 같은 행의 관찰 정보를 임시 유지 |
| 동명이인 비교 | 같은 이름의 직급·소속 비교, 모든 표시 정보가 같은 여러 행도 합치지 않고 경고 |
| 연락 준비 | 문의·진행 확인·자료 요청·감사 목적별 초안 뼈대와 선택한 연락 후보를 작성 도우미로 전달 |
| 다음 연락을 위한 보관 | 선택한 후보를 계정별 ‘연락 준비 그룹’으로 저장·불러오기·삭제. 저장 당시 시각과 현재 재확인 필요 표시 |
| 이전 자료 확인 | 발신자 이름이 정확히 일치하는 최근 보관 쪽지 최대 8건과 각 후보 쪽지의 열린 업무 최대 3건, 원문을 검색 창에서 열기 |

친구는 사람·그룹을 고른 뒤 연락 목적을 정하는 데 집중한다. 조직도는 담당업무·소속의 확인된 글자에서 연락 후보를 좁히는 데 집중한다. 자연어 담당자 추천이나 기관 전체 검색을 구현했다고 표시하지 않는다.

## 실제 화면에서 확인한 구조

Computer Use로 기존 온톡 메인 창을 열람하고 친구·조직도 메뉴를 이동했다. 실제 이름·전화·담당업무를 코드나 테스트 자료에 복사하지 않았다.

- 친구 메인 경로 `renderer/app.html#/main/1`, 조직도 경로 `renderer/app.html#/organizations`를 확인해 메뉴 판별에 추가했다. 로그인 화면 여부를 먼저 확인한다.
- 친구의 사람 목록은 이름·직급·소속 문자열·온라인 상태를 제공한다. 상단 자기 프로필은 이 목록과 구분한다.
- 그룹에는 체크박스, 표시명, 인원, 구성원 목록이 있다. 그룹의 인원 표시와 관찰한 인원은 별도로 취급한다.
- 조직도는 기관→부서→사람의 트리다. 사람 행의 이름·직급·상태와 상위 부서 경로를 분리한다.
- 사람 위의 일시 상세는 별도 도구 설명 요소에 이름·직급·직장전화·담당업무가 나타났다. 이번에 관찰한 단일 사람 클릭은 선택 신호를 제공하지 않았으므로 마우스 아래 상세를 선택으로 간주하지 않는다.

이 조사는 UI와 접근성 표시 구조의 확인이다. 새 MSAA 파서를 실행한 실제 온톡→사이드카 전체 흐름 검증과 동등하지 않다. 새 파서의 행 경계·체크/선택 상태는 합성 트리와 화면 검사로 검증했으며, 실제 연동 수용 시험은 남아 있다.

## 확인 수준과 보존 규칙

- 확인한 메인 메뉴의 현재 부착 대상에서만 사람 목록을 읽는다. 미확인 메뉴·사용자 검색·알리미·로그인에서 친구/조직도 자료를 수집하지 않는다.
- 선택 가능한 상태를 실제 선택으로 해석하지 않는다. 선택 신호가 없을 때 사이드카에서 고른 대상은 ‘사이드카에서 직접 선택’으로 표시하며 온톡 선택을 변경하지 않는다.
- 행의 주소는 현재 화면에서의 선택 유지에만 사용한다. 동일한 주소에 이름·직급·소속이 바뀌면 이전 선택을 제거한다. 사람 고유 ID를 확보했다는 뜻은 아니다.
- 같은 이름·직급의 여러 행이 있으면 도구 설명의 업무를 임의의 행에 붙이지 않는다. 온라인 상태 변화만으로 선택 대상을 바꾸지 않고 응답 가능성도 추정하지 않는다.
- 일시 상세의 캐시는 현재 창·메뉴·계정 안의 관찰 정보다. 확인 시각을 표시하고, 행이 사라지거나 표시 정보가 모호해지면 상세를 제거한다. 사용자가 그룹 저장을 누르기 전에는 연락처를 지속 저장하지 않는다.
- 접힌 부서·필터 밖 목록·읽기 한도에 도달한 부분은 전체 범위로 간주하지 않는다. 그룹/부서를 고를 때 읽은 구성원만 준비한다.
- 보관 쪽지/업무는 발신자 이름 일치 후보다. 같은 사람의 이력 또는 그 사람의 업무로 확정하지 않고 원문과 소속 확인을 안내한다. 사람과 업무의 명시적 고유 신원 연결은 아직 없다.
- 연락 후보는 작성 도우미에서 이름 검색 준비로 전달된다. 후보를 고르는 것만으로 실제 수신자·작성창을 선택하거나 전송하지 않는다. 작성창에서 소속을 확인하고 직접 추가해야 한다.
- ‘연락 준비 그룹’은 기존 작성창에서 수신자를 확인한 `recipient_group`과 별도 저장한다. 기존 그룹 자동 추가 경로로 준비 후보가 들어가지 않는다. 저장한 온라인 상태를 현재 상태처럼 표시하지 않는다.

## 저장소와 코드

저장소 버전을 **6→7**로 올려 `contact_preparation_group` 테이블을 추가했다. 기존 쪽지·업무·초안·수신자 그룹은 유지한다. 실제 이전 스키마를 열면 암호화된 `notes.db.v6.bak`를 남긴 뒤 마이그레이션한다. 버전 6까지만 아는 기존 실행 파일은 변경된 저장소를 열 수 없으므로 개발 빌드와 기존 배포판을 혼용하지 않는다. 이번 검증은 합성 저장소만 사용했으며 운영 계정 저장소를 열거나 변경하지 않았다.

| 영역 | 주요 파일 |
|---|---|
| 사람·그룹·범위·연락 목적 계약 | `src/OnTalk.Sidecar.Core/PeopleContext.cs` |
| 친구/조직도 파서 | `src/OnTalk.Sidecar.Automation/MainPeopleParser.cs` |
| 메뉴 경로·내용 감시 | `WindowContextParser.cs`, `NoteWatcher.cs`, `MsaaReader.cs` |

| 연락 준비 그룹과 보관 후보 | `src/OnTalk.Sidecar.Storage/ProfileStore.People.cs`, `ProfileStore.cs` |

## 검증 결과

- 전체 테스트 **213개 통과**. 1차 대비 17개를 추가했다. 메뉴 경로, 자기 프로필/숨긴 요소 제외, 선택 가능과 선택 구분, 그룹/부서 범위, 읽기 한도, 상세/동명이인, 후보 근거, 계정 격리·재시작·삭제, 이름 일치 후보, 버전 6 자료 보존과 마이그레이션 백업을 확인했다.
- Release 전체 빌드 **오류 0개·경고 0개**. 기존 진단 도구도 함께 빌드했다.
- 합성 WPF 검사: 기본 문맥 14종, 사람 선택 6종, 작성 도우미 2종을 두 높이로 렌더링해 **44개 이미지** 생성. 선택 변경·수동 선택 표시·일시 상세 보존·행 교체 시 선택 제거·연락 준비 전달·전송 비활성화·보관 후보 원문/신원 확인 안내와 기존 AI 제안 수락/만료 검사를 통과했다.
- 친구 사람 선택, 조직도 부서 선택, 연락 후보를 전달한 작성 도우미 이미지를 육안 확인했다.
- 실제 쪽지 전송, 연락처 추가, 온톡 그룹 수정, 예약 등록을 실행하지 않았다. 대화 분석·답변/업무 연결은 이번 단계에 포함하지 않았다.

```powershell
dotnet test tests/OnTalk.Sidecar.Tests -c Release --no-restore
dotnet build OnTalk.Sidecar.sln -c Release --no-restore
dotnet run --project tools/OnTalk.ContextPreview -c Release --no-restore -- artifacts/context-preview
```

실제 온톡에서 새 파서의 결과를 확인하는 수용 시험과 대화 메시지/참여자/확보 범위 파서가 다음 작업이다. 담당자 검색은 현재 확보한 글자의 정확한 일치로 시작하며, 자연어 검색 조건 해석과 사람별 업무의 명시적 연결은 후속 확장이다.
